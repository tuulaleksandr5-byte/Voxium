**Навигация:** [документация](docs/INDEX.md) · [план развития](docs/ROADMAP.md) · [как внести изменения](docs/CONTRIBUTING.md).

**1.0 Foundation принята пользователем и зафиксирована тегом `v1.0.0`.** Ветка `feature/2.0-progression` содержит **`2.0.0-alpha.4`: добычу по времени, четыре руды и личный крафт 2×2**. Сохранены Survival/Creative, здоровье, голод, воздух, смерть/возрождение, консоль, конечный инвентарь, дроп и сундуки из этапов 2–3. Это частичное обновление прогрессии: полный этап 4 прежнего плана включает восемь руд и ещё не завершён. [План текущего обновления](docs/superpowers/plans/2026-11-09-mining-assets-crafting.md) · [План девяти этапов](docs/SURVIVAL_V2_PLAN.md).

Подключены исходные PNG блоков, материалов, 25 инструментов и 16 частей брони. Инструменты влияют на время добычи и разрешение дропа; прочность, защита брони, крафт 3×3 и плавка пока не реализованы. Верстак и печь доступны как размещаемые блоки. Мирные животные и еда остаются в плане этапа 6. История: [этап 1](docs/STAGE_1_ANIMALS_PLAN.md), [этап 2](docs/STAGE_2_SURVIVAL.md), [этап 3](docs/STAGE_3_INVENTORY.md), [изображения инструментов](docs/TOOL_TEXTURES.md).

## Запуск

Установите [Rust через rustup](https://rustup.rs/). Версия и компоненты закреплены в `rust-toolchain.toml`, зависимости — в `Cargo.lock`.

```bash
cargo run --locked -p voxel-client
```

Для более быстрой игры после первой компиляции:

```bash
cargo run --release --locked -p voxel-client
```

На Debian/Ubuntu нужны `pkg-config`, `libasound2-dev`, `libudev-dev`, `libwayland-dev`, `libxkbcommon-dev`, `libx11-dev`, `libxcursor-dev`, `libxi-dev`, `libxrandr-dev` и Vulkan-драйвер видеокарты. На Windows нужен Rust MSVC toolchain с C++ build tools. Предыдущие сборки Windows GNU x64 проверялись через Wine/Vulkan; отдельная проверка текущей альфы описывается в материалах её выпуска. Запуск на настоящей Windows **не проверен**. Подробности: [Windows-сборка](docs/WINDOWS_BUILD.md).

В подготовленной облачной среде перед командами:

```bash
source /workspace/.voxel-env/activate.sh
cd /workspace/voxel-sandbox-rust
cargo run --locked -p voxel-client
```

Для запуска нужен графический дисплей. Headless-тесты ядра обходятся без окна/GPU; инструкции Xvfb для облачной проверки — в [отчёте проверки](docs/VALIDATION.md).

## Управление

| Клавиша | Действие |
|---|---|
| W A S D / мышь | Ходьба / обзор |
| Space | Прыжок |
| Ctrl / W дважды | Бег и ускорение полёта |
| Shift на земле | Приседание (под потолком нельзя встать) |
| 1–9 / колёсико | Выбор слота хотбара |
| Space дважды | Включить/выключить полёт в Creative |
| Space / Shift в полёте | Вверх / вниз |
| F3 | Координаты и FPS |
| F3 + G | Сетка чанков |
| E | Инвентарь; в Creative также бесконечный каталог предметов |
| ЛКМ / перетаскивание в инвентаре | Взять, положить, объединить или поменять стек |
| ПКМ в инвентаре | Взять половину стека / положить один предмет |
| Shift + клик в инвентаре | Быстрый перенос между хотбаром, рюкзаком и открытым сундуком |
| Q / Ctrl + Q | Выбросить один предмет / весь выбранный стек |
| ПКМ по сундуку | Открыть 27 слотов; Shift + ПКМ позволяет поставить блок рядом |
| ЛКМ / ПКМ | Удерживать для добычи в Survival / поставить блок на расстоянии до 6 блоков; в Creative разрушение по клику |
| ЛКМ / Shift + ЛКМ по результату крафта | Сделать одну порцию на курсор / максимум полных порций в хотбар и рюкзак |
| Esc | Пауза / продолжение |
| F5 | Сохранить мир |
| / | Консоль: `/gamemode survival`, `/gamemode creative`, `/gamerule keepInventory true`, `/gamerule naturalRegeneration false` |

Прогресс добычи и трещины появляются на выбранном блоке; смена цели, инструмента или слота, отпускание ЛКМ и открытие меню сбрасывают прогресс. Точные секунды из пользовательской таблицы хранятся в `assets/data/mining.ron`; скорость инструмента и право получить ресурс проверяются независимо. После закрытия интерфейса нужно отпустить кнопки мыши перед следующим действием в мире.

Блок нельзя установить внутри игрока. Коренная порода неразрушима. Вода в этом этапе — статические прозрачные блоки, проходимые и доступные для удаления; симуляция течения и плавание не реализованы.

Исходные текстуры из ZIP и значок приложения подключены: [отчёт](docs/ORIGINAL_TEXTURES.md). HUD, хотбар и звуки: [предыдущее обновление](docs/HUD_ICONS_AUDIO.md). Ресурсы: [инструкция](assets/README.md). Меню и управление: [предыдущее обновление](docs/VISUAL_REFRESH.md).

## Реализовано

- Главное меню, ввод имени и необязательного числового seed, выбор Survival/Creative, список сохранений, пауза.
- Этап 2 Survival: здоровье 20, голод/насыщение/истощение, регенерация, урон от падения и утопления, воздух, смерть и возрождение у спавна. Creative отключает урон и голод и разрешает полёт.
- Минимальная консоль `/gamemode` и `/gamerule`, обновление `assets/data/survival.ron` без перезапуска. Логика выживания независима от Bevy; ввод и UI передают действия через сообщения.
- Этап 3: 9 слотов хотбара + 27 рюкзака + 4 брони + вторая рука, реальные количества и стеки 64/16/1. Survival начинает пустым, установка и Q расходуют предметы; Creative имеет бесконечный каталог из 74 предметов и не расходует выбранный стек.
- Дроп с физикой, вращением, объединением, частичным подбором и настройками RON: задержка 0.5 с, радиус 1.5 блока, срок 300 с, предел 512. Сундук на 27 слотов использует общую логику инвентаря; разрушение высыпает содержимое один раз.
- Реестры предметов и настройки дропа обновляются без перезапуска; ошибочная конфигурация оставляет прежние данные. Смерть учитывает `keepInventory`, закрытие инвентаря возвращает предмет с курсора или создаёт дроп переполнения.
- Личный крафт 2×2 с отдельным результатом: бревно → 4 доски, две доски вертикально → 4 палки, квадрат досок → верстак, квадрат песка → песчаник, железный/золотой/алмазный блок → 9 соответствующих материалов. Закрытие возвращает ингредиенты в инвентарь или выбрасывает переполнение; ошибочный `recipes.ron` сохраняет рабочие рецепты.
- Добыча по точной таблице времени, учёт типа и уровня инструмента, однократный дроп после завершения. Уголь требует деревянную кирку или выше, железо — каменную или выше, золото/алмазы — железную или алмазную. Золотая кирка имеет уровень деревянной, даже когда её скорость выше. Руды дают уголь, сырое железо, сырое золото и алмаз; обычный камень по-прежнему даёт булыжник.
- Все исходные ID блоков 0…16 сохранены. Четыре руды имеют ID 17…20, железный/золотой/алмазный блоки — 21…23, верстак — 24, печь — 25. Исходные PNG и слои 0…16, включая пустой слой 17, сохранены; новые изображения добавлены отдельными слоями.
- Компактные секции 16×16×16, высоты **−64…320 включительно**, отрицательные координаты.
- Детерминированный noise-ландшафт: равнины, лес, пустыня, горы, океан; деревья, пещеры, вода. Новые миры используют генератор 2 с четырьмя рудами; старые миры сохраняют точный генератор 1.
- Фоновая загрузка ближайших чанков и построение мешей, выгрузка дальних чанков, лимит загрузок мешей за кадр.
- Greedy meshing, отсечение скрытых граней и frustum culling Bevy. ECS-сущности соответствуют мешам секций/материалам, а не отдельным блокам.
- Массив из 36 текстур 128×128: Linear + 8 мип-уровней + анизотропия ×8, повторение по greedy-граням, назначение top/side/bottom/front в RON, угловой AO, Gaussian-тени, градиент неба и дальний туман. Все 17 PNG из присланного `textures_cut.zip` сохранены без изменений и встроены в EXE; внешний атлас не требуется. Исходные материалы не заменены процедурными текстурами. [Ресурсы](assets/README.md).
- Гравитация, swept AABB-коллизии, 3D DDA, запрет движения в незагруженный чанк.
- Версионированные сохранения: seed, имя, положение/обзор, время и правки блоков. Автосохранение каждые 30 секунд, ручное сохранение и сохранение при выходе.
- Проверка целостности, синхронизированные временные файлы и резервная копия. При повреждении основной записи загрузчик читает проверенную резервную копию без изменения файлов; несовместимая версия выдаёт ошибку.
- Настройки разрешения, полноэкранного режима, дальности 4–16 чанков, мыши, VSync и общей громкости.

## Сохранения

В этой альфе по умолчанию используется отдельный каталог `saves-v2/` относительно рабочей директории запуска. Каталог Foundation `saves/` не подхватывается автоматически; для проверки старого мира скопируйте его JSON и резервную копию в `saves-v2/`. Переменная `VOXEL_SAVE_DIR` по-прежнему задаёт другой каталог.

Новые записи используют **JSON schema 2**: имя, seed, положение/обзор, время, правки блоков, версию генератора и снимок параметров руд для генератора 2. Загрузчик сначала проверяет контрольную сумму точных исходных байтов payload, затем читает строгую схему. Foundation schema 1 мигрирует в памяти в schema 2 с **генератором 1 без снимка руд**; открытие и список миров не перезаписывают файлы. При первом последующем сохранении исходные проверенные байты становятся обычной вращающейся `.bak`, а основная запись получает schema 2. Более старый EXE не открывает schema 2; сохраняйте отдельную копию перед миграцией. В старом мире можно сохранять и новые размещённые блоки.

При создании мира `assets/data/ores.ron` читается через `VOXEL_ORES_CONFIG`, каталог рядом с EXE, рабочий каталог или встроенный запасной вариант. Ошибочная внешняя конфигурация отклоняет создание мира. Уголь: Y 0…192, 20 жил по 17 кандидатов; железо: −64…72, 12 по 9; золото: −64…32, 4 по 9; алмазы: −64…16, 7 по 8. Это попытки на чанк происхождения: треугольное распределение высот центров, связные жилы, замена только камня/глубинного камня в пределах диапазона. Воздух, коренная порода и другие материалы не заменяются; фактическое число блоков может быть меньше. Соседние origins учитываются независимо от порядка загрузки и знака координат. Параметры сохраняются в мире: изменения внешнего `ores.ron` влияют только на будущие новые миры. Для загрузки генератора 2 требуется его собственный корректный снимок; текущие defaults не подставляются.

Ограничение этапа 3 остаётся: здоровье, голод, режим, gamerules, весь инвентарь, крафт, курсор, дроп и содержимое сундуков живут только в памяти и сбрасываются при закрытии мира. Runtime-сундук сохраняется как воздух (ID 0): контейнер исчезает после повторного открытия, а выемка и обычные постройки сохраняются. После открытия устанавливается Survival со свежими статами и пустым инвентарём. Состояние печи отсутствует. Schema 2 в этой альфе добавляет снимок генерации, а полное сохранение Survival остаётся задачей этапа 9.

Мир хранится в `<id>.json`, предыдущая проверенная версия — в `<id>.json.bak`. Настройки находятся в `settings.cfg` и не попадают в список миров. Не удаляйте резервные копии при ручном восстановлении. Контрольная сумма обнаруживает повреждение, но не предназначена для защиты от намеренной подделки.

## Проверки

```bash
cargo fmt --all -- --check
cargo check --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --locked -p voxel-client
```

Тесты проверяют координаты и границы, независимые контрольные значения генератора 1, диапазоны и стыки руд, снимки генератора 2, исходную контрольную сумму и миграцию сохранений, восстановление из резервных копий, постройки через отрицательную границу чанков, greedy meshing, DDA и коллизии. Проверки инвентаря/крафта покрывают сохранение количества, курсор, переполнение, смерть, контейнеры и ошибочные RON; проверки добычи — все 72 применимые ячейки пользовательской таблицы, смену цели/инструмента и однократное завершение. Клиентские тесты проверяют передачу снимка фоновой генерации и отмену очередей при смене мира. Native GUI и Windows/Wine-приёмка текущей альфы выполняются отдельно от этих автоматических проверок; исторические результаты этапа 3 относятся к прежней сборке.

## Дальнейшая проверка и ограничения

- Проверка уже собранного Windows GNU x64 EXE на настоящей Windows-машине и подготовка MSVC release-сборки.
- Профилирование на GTX 1660/1920×1080, длительные переходы через чанки и большой объём построек. **60 FPS не измерены и не гарантируются.**
- Масштабирование сохранений большого мира: сейчас сериализация и синхронизация файла выполняются на основном потоке; нужны фоновая запись и региональные данные.
- Floating origin для точности игрока/камеры на очень больших координатах.
- Полировка воды/стекла (сортировка прозрачности по мешу секции может давать артефакты), текстур, теней и интерфейса. Русский интерфейс уже добавлен.
- Более широкий ручной QA настроек/множества миров, длительная проверка сохранности и внешнее тестирование сборок.

Эта альфа реализует четыре руды из восьми прежнего этапа 4, точную добычу и семь личных рецептов 2×2. Полный этап 4, прочность инструментов, защита брони, функциональный верстак 3×3, плавка, животные, опыт/зачарования и полные сохранения Survival остаются впереди. Лава, огонь и урон от мобов имеют точки расширения в ядре; соответствующих блоков и мобов ещё нет. Враждебные мобы — к 3.0, мультиплеер — к 11.0. [Дорожная карта](docs/ROADMAP.md).
